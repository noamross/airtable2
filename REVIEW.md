# PR Review Checklist — airtable2

Refer to `AGENTS.md` and `.github/CONTRIBUTING.md` rather than restating
conventions here.

## Tests

Mocked tests pass without `AIRTABLE_TEST_LIVE` set.

Live tests require explicit reviewer approval; run them before merge.

No live API calls in `@examples` without `\dontrun{}` wrapping.

## Coding Conventions

`.token` (dotted) for `air_*` functions; `token` (undotted) for `at_*`.

Argument ordering: no-default first, defaulted second, project-level
last; main/piped object first; ID hierarchy record → field → base →
workspace.

[cli](https://cli.r-lib.org) pluralization uses `{n_x}` count variable —
not `{?s}` alone with a vector.

Tidyverse / rlang style; `|>` pipe.

## Documentation

Public API changes are reflected in roxygen docs and any relevant
vignette cross-links.

Any new Airtable API quirks discovered during this work are noted in the
API quirks section of `CONTRIBUTING.md`.

## Scope

No unrelated changes snuck in.

`man/` and `NAMESPACE` changes were generated by a dedicated
documentation pass, not mixed into feature commits.
